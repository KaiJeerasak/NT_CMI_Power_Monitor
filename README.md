# NT Chiang Mai Power Monitor

เว็บแดชบอร์ดติดตามสถานีไฟฟ้าสำรอง พัฒนาด้วย Next.js App Router, React และ TypeScript

## เริ่มใช้งานในเครื่อง

ต้องใช้ Node.js 20.9 ขึ้นไป และ pnpm

```bash
pnpm install
Copy-Item .env.example .env.local
pnpm dev
```

เปิด `http://localhost:3000` จากนั้นกำหนดค่าใน `.env.local` ตามหัวข้อด้านล่างและรีสตาร์ต Next.js เมื่อแก้ environment variables

## Environment variables

| ตัวแปร | ใช้สำหรับ |
| --- | --- |
| `NEXT_PUBLIC_LONGDO_MAP_KEY` | Longdo Map browser key ควรจำกัดโดเมนที่อนุญาตใน Longdo console |
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` | เชื่อมต่อ MariaDB เพื่ออ่านข้อมูลสถานี |
| `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY` | Auth, อนุมัติบัญชี และคอนฟิกส่วนกลาง; secret key ใช้เฉพาะบนเซิร์ฟเวอร์ |
| `STATION_STALE_AFTER_SECONDS` | อายุข้อมูลสูงสุดก่อนแสดงสถานีเป็นออฟไลน์ (ค่าเริ่มต้น 600 วินาที) |

ห้าม commit `.env.local`, รหัสผ่าน, token หรือ key จริง ใช้ `.env.example` เป็นเพียงรายการชื่อตัวแปรและค่าตัวอย่างเท่านั้น

## ฟังก์ชันหลัก

- ภาพรวมสถานีบนแผนที่ พร้อมสถานะและรายการแจ้งเตือนล่าสุด
- API อ่านข้อมูลปัจจุบันจาก MariaDB โดยใช้ `site_cmi`; ประวัติอ่านจาก `site_log`
- กฎ Alarm แรงดัน AC ต่ำกว่า 150 V และสถานะอุปกรณ์ที่กำหนดรายสถานี
- ศูนย์แจ้งเตือนพร้อมการรับทราบเหตุ และข้อมูลเหตุไฟฟ้าขัดข้อง/แรงดัน DC
- ประวัติ กราฟแนวโน้ม และส่งออก CSV ตามช่วงเวลาที่เลือก
- ตั้งค่าระบบไฟฟ้า Battery Backup และเครื่องกำเนิดไฟฟ้ารายสถานี
- ระบบ login/ลงทะเบียนถูกปิดชั่วคราว; เปิด dashboard และอ่านข้อมูลสถานี/ประวัติได้โดยไม่ต้องเข้าสู่ระบบ
- เมนูตั้งค่าสถานีและจัดการผู้ใช้เปิดให้ผู้เข้าชมทุกคนใช้งานชั่วคราว
- ปุ่มจำลองเหตุการณ์บนหน้าเว็บ ใช้แสดงผลเท่านั้น ไม่เขียนฐานข้อมูลหรือสั่งอุปกรณ์จริง

## ขอบเขตและข้อควรทราบ

การเชื่อมต่อ MariaDB ใช้อ่านข้อมูลสถานี/ประวัติ ส่วน Supabase ใช้ Auth, การอนุมัติบัญชี และคอนฟิกส่วนกลาง ตาราง/นโยบายที่ใช้งานอยู่บันทึกไว้ใน `supabase/schema.sql` ช่วงนี้หน้า login ปิดอยู่ และหน้า/API อ่านข้อมูลสถานี ประวัติ คอนฟิก รวมถึงอนุมัติ/ระงับผู้ใช้เปิดสาธารณะ ทุกคนที่เข้าเว็บจึงแก้คอนฟิกและสถานะผู้ใช้ได้; API ใช้ `SUPABASE_SECRET_KEY` เฉพาะบนเซิร์ฟเวอร์เพื่อเขียนข้อมูลโดยไม่เปิดเผยคีย์แก่เบราว์เซอร์

สำหรับบัญชีเริ่มต้น สร้างไฟล์ `.env.bootstrap` ในเครื่องผู้ดูแล โดยกำหนด `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `BOOTSTRAP_ADMIN_PASSWORD`, `BOOTSTRAP_USER_PASSWORD` แล้วรัน `pnpm bootstrap:users` สคริปต์จะสร้างบัญชี `jeerasak` (Admin) และ `user1` (User) หากยังไม่มี แล้วกำหนดสถานะเป็นอนุมัติ ไฟล์ `.env*` ถูก ignore ไว้ ห้าม commit ไฟล์นี้ และควรเปลี่ยนรหัสผ่านทดสอบหลังเข้าสู่ระบบครั้งแรก

ก่อน deploy ต้องตั้ง `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` และ `SUPABASE_SECRET_KEY` ใน Vercel Production; ห้ามใช้ prefix `NEXT_PUBLIC_` กับ secret key ตรวจ RLS และสิทธิ์ Data API ก่อนเปิดให้ผู้ใช้จริง ระบบยังไม่มี audit log สำหรับการเปลี่ยนคอนฟิก

ค่า `load_dc` และ `wifi` ยังคงแสดงเป็นค่าดิบจนกว่าจะยืนยันหน่วย ส่วนพิกัดสถานีควรตรวจสอบกับตำแหน่งจริงก่อนนำไปใช้ปฏิบัติงาน
